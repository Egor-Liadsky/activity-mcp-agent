# activity-mcp-agent

MCP-сервер активности git-проектов на Rust. Демон постоянно следит за
каталогом, в котором лежит много проектов, и записывает в SQLite, что в них
менялось: новые коммиты, ветки, переключения веток, появление и исчезновение
проектов, незакоммиченное. По расписанию (cron) из журнала собирается
сводка, а MCP-клиент (например, консольный
[`agentcli`](https://github.com/Egor-Liadsky/agent-cli)) показывает её
человеку и даёт модели инструменты для вопросов о журнале.

В отличие от [`git-mcp`](https://github.com/Egor-Liadsky/git-mcp-agent),
который клиент запускает процессом на время чата, этот сервер работает
круглосуточно под launchd или systemd. Поэтому основной транспорт —
Streamable HTTP на loopback-адресе: клиенты приходят и уходят, а сбор
изменений и сводки по расписанию идут и без них. Транспорт stdio тоже есть:
флаг `--stdio` открывает базу работающего демона для клиентов, которые умеют
только запускать сервер процессом.

## Устройство

Cargo workspace (Rust edition 2024) из одного крейта:

| Крейт          | Каталог           | Что это                                               |
|----------------|-------------------|-------------------------------------------------------|
| `activity-mcp` | `crates/activity` | библиотека `activity_mcp` и бинарник `activity-mcp`   |

```
 notify (FSEvents/inotify) --> «грязные» проекты --+
                                                   v
 полный обход раз в --rescan-interval -------> collector --> SQLite
                                                   (git log, status)   |
 расписание --schedule (cron) --> digest ------------------------------+
                                                                       v
 клиент <-- Streamable HTTP /mcp (или --stdio) <-- инструменты activity_*
```

- `src/discovery.rs` — поиск репозиториев под корнями (до `--max-depth`,
  подмодули — отдельные проекты) и сопоставление пути файла с проектом;
- `src/daemon.rs` — фоновые циклы и HTTP-маршруты; подписка `notify` в нём
  лишь помечает проект, чтобы опросить его раньше срока, а источник правды —
  всегда git;
- `src/collector.rs` — опрос проекта: курсоры веток, новые коммиты
  (`git log <вершина> --not <курсоры>`), смена текущей ветки, снимок
  незакоммиченного;
- `src/git.rs` — вызовы системного `git` только на чтение, с
  `GIT_OPTIONAL_LOCKS=0`, чтобы фоновый `git status` не брал `index.lock` и
  не мешал коммиту человека;
- `src/digest.rs` — сводка за период: JSON и готовый markdown на русском;
- `src/schedule.rs` — cron в местном времени, пропущенный запуск;
- `src/server.rs` — MCP-инструменты; `src/store.rs` и `migrations/` —
  SQLite;
- `tests/protocol.rs` — демон в процессе теста на случайном порту и
  `--stdio` настоящим процессом, оба — через MCP-клиент `rmcp`.

| Назначение              | Крейты                                                                 |
|-------------------------|------------------------------------------------------------------------|
| MCP-сервер              | `rmcp` (server, macros, transport-io, transport-streamable-http-server) |
| HTTP                    | `axum`                                                                 |
| Хранилище               | `sqlx` (SQLite, миграции)                                              |
| Файловые события        | `notify`                                                               |
| Расписание и время      | `cron`, `chrono`                                                       |
| Флаги, журнал           | `clap`, `tracing`, `tracing-subscriber`                                |

## Установка

```bash
cargo install --git https://github.com/Egor-Liadsky/activity-mcp-agent activity-mcp
```

Из локальной копии (в зонтичном репозитории
[`agent`](https://github.com/Egor-Liadsky/agent) она лежит подмодулем
`mcp/activity`):

```bash
cargo install --path crates/activity
```

Нужен `git` в `PATH` — демон вызывает его сам.

## Запуск

```bash
activity-mcp --root ~/projects
```

| Флаг                     | По умолчанию          | Что задаёт                                                    |
|--------------------------|-----------------------|---------------------------------------------------------------|
| `--root <КАТАЛОГ>`       | обязателен            | каталог с проектами; флаг можно повторить                     |
| `--listen <АДРЕС>`       | `127.0.0.1:7878`      | адрес HTTP; не loopback — отказ стартовать                    |
| `--db <ФАЙЛ>`            | `<data-dir>/activity-mcp/activity.db` | база SQLite (на macOS data-dir — `~/Library/Application Support`) |
| `--schedule <CRON>`      | `0 9,18 * * *`        | когда собирать сводку: 5 полей или 6–7 с секундами, местное время |
| `--rescan-interval`      | `1h`                  | полный обход проектов: новые репозитории, потерянные события  |
| `--max-depth`            | `3`                   | глубина поиска репозиториев под корнем                         |
| `--exclude <ИМЯ>`        | —                     | ещё одно имя каталога, который не обходится и не наблюдается   |
| `--retention`            | `90d`                 | срок хранения событий и сводок                                 |
| `--no-watch`             | выкл.                 | без файловых событий, только полный обход по таймеру           |
| `--token-file <ФАЙЛ>`    | —                     | требовать от клиентов `/mcp` заголовок `Authorization: Bearer` |
| `--stdio`                | выкл.                 | MCP через stdin/stdout поверх базы работающего демона          |

Длительности — `90s`, `15m`, `6h`, `7d`, `2w`. Каталоги сборки и
зависимостей (`target`, `node_modules`, `build`, `dist`, `.venv` и др.) не
обходятся и не будят опрос. Журнал — в stderr, уровень — `RUST_LOG` (по умолчанию `info,rmcp=warn`: без записи на каждое подключение клиента).

Маршруты:

- `POST/GET/DELETE /mcp` — MCP Streamable HTTP;
- `GET /healthz` — живость без токена: число проектов, корни, расписание,
  время следующей сводки.

### Как считаются изменения

- При первом знакомстве с проектом запоминаются только вершины веток:
  история до этого момента — не изменения периода.
- Новые коммиты — достижимые от новой вершины и недостижимые от курсоров.
  Новая ветка не приносит историю ветки, от которой отведена; коммит,
  попавший в несколько веток (слияние), записывается один раз.
- Время события — когда демон его заметил, а не дата коммита: подтянутый
  `git pull` месячной давности попадает в текущий период.
- Больше 200 новых коммитов за опрос одной ветки не записывается — это импорт
  чужой истории, а не работа за период.
- Сводка покрывает время от конца предыдущей до сейчас. Период без событий
  сводки не создаёт и переходит в следующий. Незакоммиченное показывается у
  активных проектов и отдельной строкой у остальных, но само по себе сводку не
  создаёт. Если демон проспал запуск по расписанию (машина была выключена),
  сводка собирается сразу после старта.

## Автозапуск

macOS — `contrib/launchd/com.github.egor-liadsky.activity-mcp.plist`
(`RunAtLoad`, `KeepAlive`). Заменить в нём пути и:

```bash
cp contrib/launchd/com.github.egor-liadsky.activity-mcp.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.github.egor-liadsky.activity-mcp.plist
curl -s http://127.0.0.1:7878/healthz
```

Linux — пользовательский unit `contrib/systemd/activity-mcp.service`
(команды установки — в его заголовке).

## Инструменты

Ответы — JSON-текст. Время — RFC 3339 в местном поясе.

| Инструмент              | Аргументы                                         | Что делает                                                   |
|-------------------------|---------------------------------------------------|--------------------------------------------------------------|
| `activity_digest`       | `unread_only` (true), `limit` (5)                 | сводки, новые первыми: `id`, период, `acked`, `text`          |
| `activity_ack`          | `id`                                              | отмечает сводку прочитанной                                   |
| `activity_projects`     | —                                                 | проекты: путь, ветка, незакоммиченное, последняя активность   |
| `activity_changes`      | `project`, `since` (`7d`), `limit` (50, до 500)   | журнал изменений, новые первыми                               |
| `activity_build_digest` | —                                                 | сводка сейчас, вне расписания (с прошлой сводки)              |

`since` — `24h`, `7d`, дата `2026-09-01` (местная полночь) или RFC 3339;
`project` — имя из `activity_projects` или абсолютный путь.
`activity_ack` и `activity_build_digest` меняют состояние демона: клиенту
стоит не давать их модели.

## Подключение к клиентам

`agentcli` (сводки в TUI по `Ctrl+A`, команды `agentcli activity …`) умеет
и сам запустить демон: `Ctrl+P` → «Сводки активности» → «Демон», `Enter`,
или `agentcli activity start`. Он пишет тот же LaunchAgent (метка
`com.github.egor-liadsky.activity-mcp`) или unit `activity-mcp.service` с
каталогом и расписанием из своего конфига и регистрирует его; ручная
установка из `contrib/` при этом не нужна.

```bash
agentcli config activity set on --root ~/projects
agentcli activity start                          # launchd / systemd --user
agentcli config activity set --chat-tools true   # инструменты activity_* модели
```

Клиенты, которые запускают сервер только процессом, — через `--stdio`:

```json
{ "command": "activity-mcp", "args": ["--stdio"] }
```

## Разработка

```bash
cargo build --release
cargo test                               # включая протокол HTTP и --stdio
cargo clippy --all-targets -- -D warnings
cargo run --release -- --root <каталог> --schedule "* * * * *"   # сводка каждую минуту
```
